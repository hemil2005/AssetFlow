# AssetFlow v0.3.0

**Status:** release candidate, **gate PASS on `integration/v03` @ `0baf71e`**. Previous release:
v0.2.0 @ `b7c2331`. The tag is cut by the release owner after merge, not in this document.

## Summary

v0.3.0 completes the notification matrix from the spec, fixes timezone day-bounds, closes the
signup-invitation and activity-log head gaps from the v0.2.0 audit, and adds a Recent activity panel
and Mark all read to the dashboard. No new addons; the six-addon boundary is unchanged.

## Shipped in v0.3.0

| Area | What shipped | Where |
|------|--------------|-------|
| Notification matrix | Allocation to holder + department head with asset chatter; return chatter; transfer requested -> head/manager, approved/rejected -> requester and both holders; booking created/cancelled -> booker + department head. `_notify_once` deduplicates per user/type/title/record/day | `assetflow_assets`, `assetflow_booking`, `assetflow_base` |
| Timezone (M18) | KPI "today" and heatmap ranges use user-timezone UTC bounds; maintenance aging dedupe uses UTC day start; legacy timezone aliases are normalized with a UTC fallback before any SQL conversion | `assetflow_reports`, `assetflow_maintenance` |
| Signup (M20) | Invitation-token signups stay portal with no Employee row; self-service signup still creates an internal role-less Employee. New HttpCase covers the token/no-token distinction | `assetflow_base` |
| Activity log (M32) | Stored, indexed `department_id` on log rows derived from the record/asset/actor; Department Head gets read-only ACL and a scoped rule (row department OR actor department), the menu, a Department column and group-bys. Employees keep no access | `assetflow_base` |
| Dashboard | Operations-board UI with a Recent activity panel (rule-filtered log rows) and Mark all read in the Notifications panel; department heads get rule-filtered activity rows rather than none | `assetflow_reports` |

## Findings found during the gate and resolved

1. **Legacy timezone crash (found on `ec0a163`, fixed by `07f4b6f`).** The browser dashboard showed
   "The dashboard could not load. Odoo Server Error" because `_read_group` emitted
   `timezone('Asia/Calcutta', ...)` and PostgreSQL rejected the legacy alias. The fix normalizes
   aliases and falls back to UTC; the regression test covers `Asia/Calcutta`. Re-verified on
   `0baf71e` as PASS.
2. **Dashboard features dropped by the operations-board rewrite (found on `580bf9d`, fixed by
   `0baf71e`).** The rewrite removed the Recent activity panel and Mark all read button while the
   RPC payloads and tests remained. `0baf71e` restores both in the new design; verified by browser
   click-through above.

## Verification method

- Fresh Odoo 19 + PostgreSQL 16 database, install all six addons with `--without-demo --test-enable`
  and all six `--test-tags`; require exit 0, zero failures/errors, no tracebacks.
- Demo seed and narrative are executed against that same DB after install; their marker lines and
  exit codes are evidence that the notification matrix did not break the walkthrough.
- Roles and menus are checked with real users in `odoo-bin shell`, exercising ACLs and record rules
  rather than view visibility alone.
- The dashboard is clicked in a real browser with the machine's `Asia/Calcutta` timezone, because the
  two bugs above were invisible to the test suite (which runs with a UTC context).

## Known gaps

- **Pre-upgrade activity logs have no `department_id`.** After upgrading, Department Heads see no
  historical log rows created before this release; managers/admins still see all rows.
- No deployment target beyond local Docker Compose and an Odoo 19 source install; no hosted demo.
- Deferred from the v0.2.0 audit and still open: M28 (extra OWL mount test), M29
  (`assertRaises(Exception)` tightening), M30 (button-level `groups=` polish), M35 (category
  translated-name uniqueness), plus deletion/sequence edge cases.
- Demo credentials are local-only; change `ASSETFLOW_DEMO_PASSWORD` and the stock `admin` password
  before any non-local reuse.

## Upgrade notes

- Update the six modules (`-u assetflow_base,...,assetflow_reports --stop-after-init`). Existing
  activity-log rows are not backfilled with a department by this release; see Known gaps.
- Existing users keep their roles. Invitation-token recipients now stay portal; only self-service
  signup creates an internal Employee.
- `./scripts/demo.ps1` drops and recreates its target database; point it only at a disposable DB.
