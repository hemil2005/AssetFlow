# AssetFlow v0.3.0

**Status:** release candidate at `integration/v03` @ `ec0a163`. Previous release: v0.2.0 @ `b7c2331`.
**Gate BLOCKED — do not tag.** The test suites pass, but the browser check found a dashboard failure
for legacy timezone aliases; see [Blocking finding](#blocking-finding). The tag is cut by the release
owner after a green re-gate, not in this document.

## Summary

v0.3.0 completes the notification matrix from the spec, fixes timezone day-bounds, closes the
signup-invitation and activity-log head gaps from the v0.2.0 audit, and adds a Recent activity panel
and Mark all read to the dashboard. No new addons; the six-addon boundary is unchanged.

## Shipped in v0.3.0

| Area | What shipped | Where |
|------|--------------|-------|
| Notification matrix | Allocation to holder + department head with asset chatter; return chatter; transfer requested -> head/manager, approved/rejected -> requester and both holders; booking created/cancelled -> booker + department head. `_notify_once` deduplicates per user/type/title/record/day | `assetflow_assets`, `assetflow_booking`, `assetflow_base` |
| Timezone (M18) | KPI "today" and heatmap ranges use user-timezone UTC bounds; maintenance aging dedupe uses UTC day start | `assetflow_reports`, `assetflow_maintenance` |

| Dashboard | Recent activity panel (rule-filtered log rows for manager/admin and heads) and Mark all read in the Notifications panel; department heads get rule-filtered activity rows rather than none | `assetflow_reports` |

  and all six `--test-tags`; require exit 0, zero failures/errors, no tracebacks.

  rather than view visibility alone.

## Blocking finding

Browser check as `maya.manager` on the dashboard action: **"The dashboard could not load. Odoo Server
Error."** Network capture shows `get_kpi_data` and `get_recent_activity` returning HTTP 200 with
results, while `get_booking_heatmap` returns
`psycopg2.errors.InvalidParameterValue: time zone "Asia/Calcutta" not recognized`. The browser sends
context `tz: "Asia/Calcutta"`. Reproduced outside the browser: with_context(tz='Asia/Calcutta') fails
the same way; `Asia/Kolkata` and `UTC` succeed. The M18 timezone day-bounds/heatmap work passes a
legacy timezone alias into SQL date grouping. Impact: the dashboard is unusable for users whose
browser timezone is such an alias, and the Recent activity panel / Mark all read button could not be
clicked because the page never rendered. Requires a fix and a full re-gate before tagging.

## Known gaps

- **Browser UI interaction remains unverified** because of the blocking dashboard failure above.
  The Recent activity panel and Mark all read were verified only at the endpoint and rule-filtered
  data level.
- **Pre-upgrade activity logs have no `department_id`.** After upgrading, Department Heads see no
  historical log rows created before this release; managers/admins still see all rows.
- No deployment target beyond local Docker Compose and an Odoo 19 source install; no hosted demo.
- Deferred from the v0.2.0 audit and still open: M28 (extra OWL mount test), M29
  (`assertRaises(Exception)` tightening), M30 (button-level `groups=` polish), M35 (category
  translated-name uniqueness), plus deletion/sequence edge cases.
- Demo credentials are local-only; change `ASSETFLOW_DEMO_PASSWORD` and the stock `admin` password
  before any non-local reuse.

## Upgrade notes

- Update the six modules (`-u assetflow_base,...,assetflow_reports --stop-after-init`). Existing
  activity-log rows are not backfilled with a department by this release; see Known gaps.
- Existing users keep their roles. Invitation-token recipients now stay portal; only self-service
  signup creates an internal Employee.
- `./scripts/demo.ps1` drops and recreates its target database; point it only at a disposable DB.
