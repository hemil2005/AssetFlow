# AssetFlow v0.2.0

**Status:** release candidate. Final gate PASS on `main` @ `423bcc0`. Previous release: v0.1.0 @
`ca42c8b`. The release tag is cut by the release owner after this gate; this document does not tag.

## Summary

v0.2.0 turns the feature-complete v0.1.0 build into a repeatable, demonstrable release: a one-command
local demo with seed and narrative, daily overdue-return notifications, an actionable notifications
UI, the HTTP signup path, computed QR asset labels with a printable label report, two-job CI, and a
batch of correctness hardening. No new addon was introduced; the six-addon boundary is unchanged.

## Verification method

- Fresh Odoo 19 + PostgreSQL 16 database; install all six addons in dependency order with
  `--without-demo --test-enable` and all six `--test-tags`; require exit 0, zero failures/errors and no tracebacks.
- CI repeats the same command in the `odoo:19.0` container, then runs `scripts/demo_smoke.ps1`, which
  asserts the seed KPI block, seed and narrative markers, and the absence of tracebacks/CRITICAL.
- Integrity guarantees were probed separately with parallel writers and forced row locks, because
  sequential unit tests cannot prove the lock behaviour.

## Known gaps and deferred work

- **No deployment target** beyond local Docker Compose and an Odoo 19 source install. No hosted
  demo, staging, or production environment is provided.
- **Trusted-context residual:** `with_context(allow_state_write=True)` still bypasses asset lifecycle
  guards via RPC. It is an internal trusted path for workflow code, not reachable from normal forms;
  ordinary form/RPC writes are guarded.
- **PDF rendering** of the QR label requires wkhtmltopdf (present in `odoo:19.0`, absent on the
  source-install verification box). HTML rendering and tag content are covered by tests.
- **v0.3 backlog:** notification matrix from spec §6 (allocation/return, transfer created/approved,
  booking created/cancelled) with idempotence tests; timezone day-bounds (M18) in reports
  KPI/heatmap and maintenance aging; signup invitation path (M20); activity-log department-head
  ACL/rule (M32); low-cost UI group polish.
- **Deferred and documented, not release blockers:** category translated-name uniqueness (M35),
  extra OWL mount test (M28), tightening `assertRaises(Exception)` (M29), button-level `groups=`
  polish (M30), and deletion/sequence edge cases.
- Demo password is local-only (`ASSETFLOW_DEMO_PASSWORD`, default `AssetFlow!2026`) and the built-in
  `admin` keeps the stock password on a fresh DB. Change both before any non-local reuse.

## Upgrade notes

- From v0.1.0: update the six modules (`-u assetflow_base,...,assetflow_reports --stop-after-init`).
  The audit duplicate-sequence migration was already shipped in v0.1.0; v0.2.0 adds no data migration.
- Existing users keep their roles; signup changes affect only newly created accounts.
- `./scripts/demo.ps1` drops and recreates its target database. Point it only at a disposable demo DB.
